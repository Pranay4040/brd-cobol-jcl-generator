## 3. The data rule

This is the rule that matters most in practice.

> **Code moves personal → office. Company data never moves the other way.**

Nothing confidential enters this repository. Ever.

**Never commit:**

- `config/shop.yml` — real job card values, HLQs, PROC names, naming rules
- `copybooks/` — real COBOL copybooks
- `input/` — real business requirements documents
- `output/` — generated artefacts derived from real inputs
- `input/golden/` — the real BRD + COBOL + JCL golden set
- Any `.cpy` / `.CPY` file
- Real dataset names, account codes, LPAR names, userids, or hostnames — in
  code, in comments, in commit messages, in issue titles, or in test fixtures

All of the above are excluded by `.gitignore`. **`.gitignore` is a safety net,
not a substitute for checking.** Run `git status` before every commit and read
what you are about to stage.

**Committed test data is synthetic.** Everything under `samples/` is invented for
this project. If a sample file starts resembling a real record layout, replace
it.

### If confidential data is committed by mistake

1. Do not just delete it in a follow-up commit — the data stays in git history.
2. Stop pushing.
3. Report it through the organisation's information-security process.
4. Treat any exposed credential or identifier as compromised and rotate it.

## 4. AI-generated output is draft material

The pipeline uses a language model at two stages: BRD → spec, and PROCEDURE
DIVISION logic. Output from both is **draft**, not deliverable.

- Zone 1 COBOL (IDENTIFICATION / ENVIRONMENT / DATA divisions) is generated
  deterministically from copybooks and config. Review is a glance.
- **Zone 2 COBOL (PROCEDURE DIVISION) is model-generated and needs real review.**
  Expect roughly 70–80% correct on first pass, and expect the failures to be
  *quiet* — code that compiles cleanly and produces a wrong number.

Zone 2 review must be done by someone who understands the business rules, not
only COBOL syntax. Generated code is marked in-file so reviewers know where to
spend attention.

**The stage 4 human approval gate is mandatory.** It must not be removed,
automated, or bypassed with a flag. Nothing generated by this pipeline goes to a
production LPAR without a named human having reviewed and approved it.

## 5. Model access

Model access is **GitHub Copilot only**, through VS Code custom agents.

There are no API keys in this project. Do not add `ANTHROPIC_API_KEY`,
`OPENAI_API_KEY`, or any other credential handling. Any code reaching for an API
key is out of policy and will not be accepted.

Anyone using this tooling remains subject to the licensed organisation's own AI
acceptable-use policy. Where that policy is stricter than this document, it wins.
